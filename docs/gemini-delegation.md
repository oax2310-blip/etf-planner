# 제미나이 위임 평가

제미나이에 어디까지 맡길지 정하기 위한 시험 기록과 잠정 판단이다. 최종 결정 전까지는 [CLAUDE.md의 GPT·제미나이 작업 위임](../CLAUDE.md) 규칙이 우선한다. 아래 시험 중 그 규칙의 금지 범위(푸시·수집 저장소)에 든 것은 사용자가 시험용으로 따로 허용한 예외다.

## 잠정 판단

- **특징:** 함수·위치·동작·테스트 항목을 정해 주면 범위를 지키며 정확히 구현한다. 지시 밖의 위험이나 설계 빈틈은 스스로 찾거나 되묻지 않는다.
- **맡겨도 됨:** 바꿀 파일·위치·결과가 다 정해지고 기존 테스트로 바로 확인되는 작은 수정. 문구·문서 정리.
- **조건부:** 설계가 끝나 함수·위치·관찰할 결과까지 적어 줄 수 있는 구현(여러 파일 가능). 병합 전에 Claude나 GPT가 검토한다. 비공개·보안 영역은 이득이 작다. 설계·프롬프트·검토에 드는 토큰이 GPT나 Claude가 직접 하는 것과 비슷해진다.
- **맡기지 않음:** 원인 분석·설계 판단, 위험을 스스로 판단해야 하는 일, 토큰·Secrets·권한·워크플로, 수집 저장소 병합 결정.

## 평가 기준

시험마다 아래 항목을 같은 방식으로 기록한다.

1. **범위:** 지정한 파일·위치만 바꿨는가.
2. **정확성:** 지시한 동작이 그대로 구현됐는가.
3. **규칙:** CLAUDE.md·AGENTS.md(보안 경계, 버전 올림, 개인정보 금지, 병합 금지 지시)를 지켰는가.
4. **검증:** 테스트·CI가 통과하는가. 핵심 줄을 하나씩 일부러 고장 냈을 때 테스트가 잡는 비율은 얼마인가.
5. **자기 점검:** 지시 밖의 위험·설계 빈틈을 스스로 찾아 보고했는가. GPT·Claude와 갈리는 가장 큰 차이로 본다.
6. **비용:** Claude가 설계·프롬프트·검토에 쓴 노력(낮음·중간·높음) 대비 아낀 양.

판정은 세 가지다. 합격은 수정 없이 병합할 수 있는 경우다. 조건부 합격은 작은 보완 뒤 병합하는 경우다. 불합격은 다시 하거나 다른 곳에 맡겨야 하는 경우다.

## 최종 결정 방법

- **범위 확대:** 4(자기 점검)와 5(덜 정해진 지시)가 합격이면 "공개 앱의 여러 파일 구현(보안·계산·고정 실행 파일 제외)"까지 넓힌다. 병합 전 검토는 유지한다.
- **현재 범위 유지:** 4가 불합격이면 지금의 잠정 판단을 유지한다. 구현을 맡길 때는 관찰할 결과까지 프롬프트에 적고 검토 뒤 병합한다.
- **결과와 상관없이 유지:** 원인 분석·설계 판단, 토큰·Secrets·권한·워크플로, 수집 저장소 병합 결정은 맡기지 않는다.
- 결정하면 CLAUDE.md의 "GPT·제미나이 작업 위임" 절을 고치고, 이 문서는 근거 기록으로 남긴다.

## 프롬프트 작성 요령

- 테스트 기대값은 관찰할 결과로 적는다. 예: "각 실행마다 나간 알림 수를 확인한다."
- "지시 밖에서 발견한 위험·빈틈은 고치지 말고 PR의 남은 위험에 적는다"를 넣는다.
- 기존 코드의 안전장치(시간·횟수 제한, 재시도 기간)와 같은 수준을 맞추라고 적는다.
- 병합 금지와 `main` 직접 push 금지를 적는다. 관련 규칙은 요약하지 않고 원문 그대로 옮긴다.

## 권한 운영

- 비공개 수집 저장소는 시험할 때만 그 저장소 하나를 임시로 허용하고, 검토가 끝나면 회수한다. 영구 허용하지 않는다. 쓰기 권한이 있으면 `main` 병합으로 Secrets를 쓰는 수집 작업까지 닿을 수 있고, 저장소 맨 위의 개인 기록 사본도 읽힌다.
- 시험 PR은 병합하지 않게 하고, 병합은 검토 뒤 사용자가 결정한다.
