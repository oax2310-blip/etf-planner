# 매매 플래너

개발·인수인계 지침: [AGENTS.md](AGENTS.md). Claude Code는 [CLAUDE.md](CLAUDE.md)를 통해 같은 지침을 읽습니다.

공개 페이지: https://oax2310-blip.github.io/etf-planner/

코드는 공개됩니다. 실제 보유 종목·수량·메모·손익은 코드나 이 저장소에 적지 마세요. 입력한 기록은 브라우저와, 연결했다면 내 GitHub **비공개 데이터 저장소**에만 저장됩니다.

## 기기 간 동기화 준비 (처음 한 번)

기존 사용자는 먼저 비공개 수집 저장소의 `docs/repository-separation.md`에 따라 데이터 복사·검증·권한 전환을 완료합니다. 기존 기록을 지우거나 빈 저장소에 새로 덮어쓰지 마세요.

1. 데이터 저장소 `etf-planner-records`는 **Private**, Actions **Disabled**, Secrets·실행 코드·워크플로 없이 준비합니다. 기존 `etf-planner-data`는 KIS 수집용으로 유지합니다.
2. 데이터 fine-grained PAT는 **Only select repositories → etf-planner-records 하나**, **Contents → Read and write**만 지정합니다. 기기별로 발급합니다.
3. 즉시수집용 별도 fine-grained PAT는 **Only select repositories → etf-planner-data 하나**, **Issues → Read and write**만 지정합니다. Contents·Actions·Workflows·Secrets·Administration은 부여하지 않습니다.
4. 사이트 **동기화**에서 새 데이터 저장소와 두 토큰을 각각 입력합니다. 즉시수집을 쓰지 않는 기기에는 Issues 토큰을 넣지 않아도 됩니다. 즉시수집 토큰이 없으면 자동수집과 데이터 동기화는 유지되고 수동 요청만 안내 후 대기합니다. 두 토큰을 하나로 합치지 마세요.
5. 정상 전환을 확인하면 기존 수집 저장소 Contents 쓰기를 가진 브라우저 PAT를 폐기합니다. 실제 권한은 발급 설정과 비공개 수집 저장소의 `scripts/check_token_boundary.py`로 함께 확인합니다. 값은 대화·문서·로그에 적지 않습니다.

세 페이지는 보안 정책(CSP)으로 이 사이트의 스크립트만 실행하고 이 사이트·GitHub API로만 통신합니다. 같은 `oax2310-blip.github.io` 주소의 다른 GitHub Pages 사이트는 이 브라우저 저장소(토큰)를 함께 읽을 수 있으므로 이 계정에서 다른 Pages 사이트를 열지 마세요.

Contents 권한은 파일별로 제한할 수 없습니다. 데이터 토큰은 그 저장소의 다른 파일도 수정할 수 있지만, 데이터 저장소는 실행하지 않고 수집기는 허용 JSON만 읽습니다. Issues 토큰의 요청 남발 위험은 남습니다.

## 규칙

- 시선·일선·주선·월선의 구간 매수는 시작선·⅓·⅔ 지점에서 사고 다음 선에 도달하면 별도로 삽니다. 달러선물·분할매수·재매수 설정과 점검 결과는 [가격 3등분 안내](docs/price-thirds.md)에 있습니다. 분할매도는 기존 방식입니다.
- 분할매수·분할매도는 회차의 **누적 체결** 칸에 실제 체결한 총주수만 넣습니다. 계획 10주 중 7주를 입력하면 자산에는 7주만 반영하고 부분 체결로 남습니다(분할매수는 회차 이름 아래 **남은 3주**, 분할매도는 **남은 매도 3주**). 추가 3주가 체결되면 누적 수량을 **10**으로 고칩니다(추가분만 자산에 반영). 체크는 잔량까지 전량 체결, 0 입력·완료 체크 해제는 해당 회차 체결과 자산 반영 취소입니다. 평가액만 있는 계획도 기준가·환율로 계획 주수를 내림해 계산합니다. 체결금액을 따로 입력하지 않으며, 배분 계산에 필요한 금액은 주수로 자동 계산합니다. 부분 체결은 완료 회차 수에 넣지 않고, 켜 둔 알림도 유지합니다.
- 분할매도의 **전액매도**는 모든 평균선을 이탈해 종료 기준선을 쓸 수 없을 때를 위한 계획입니다. 계획 추가·수정 창에서 종료 기준선 단위를 **% 하락 · 기준선 없음**으로 고르고 하락률을 넣으면, 직접 정한 시작 기준가부터 그 비율만큼 내린 가격(자동 계산)까지 보유 전량(매도 비중 100%)을 분할 횟수로 나눠 팝니다. 회차 가격·수량·누적 체결·자산 반영·알림은 기존 분할매도와 같습니다. 이 계획에만 **계획 진행** 카드의 다음 회차 줄 아래에 재매수의 **손절 도달 기준**과 같은 한 줄 표식(**전액 매도** · −N% · 종료가 · 시작가 · 분할 횟수 · 상태)이 보이며, 현재가가 시작 기준가 이하가 되면 **전액매도 시점**(종료가 이하이면 **하락 끝 도달**)을 주황색으로 표시하고 왼쪽 계획 카드의 회차 수도 같은 색으로 표시합니다. 시세가 없거나 지난 시세이면 판단하지 않습니다. 보유 종목은 기존 **연결된 전체 보유 종목**에서 봅니다. 하락률은 `plans[].endPct`에 저장하고 종료 기준선 이름은 `시작가 −N%`로 두어 시세가 종료 기준가를 덮어쓰지 않습니다. 종료 기준선이 있는 기존 계획은 그대로입니다.
- 분할매도 상세 화면의 **계획 진행** 카드는 분할매수 진행 카드와 같은 모양입니다. 회차마다 한 칸인 띠(오른쪽이 1회)가 처음에는 모두 차 있고(남은 매도 초록), 매도 완료 회차는 오른쪽부터 빈 칸, 부분 체결은 남은 비율만큼만 채웁니다(도달·부분 체결 주황, 다음 회차 파랑). 다음 회차 칸 앞에 **현재가** 이름표, 오른쪽 끝에 첫 매도·왼쪽 끝에 마지막 매도 기준가와 선 이름(달러 계획은 원화 환산), 가운데에 상태·도달/부분 체결 칩·완료/전체 회차, 그 아래 보유(또는 매도·남은 수량)·평가액과 다음 회차 가격·남은 %를 보여 줍니다. 첫 매도 기준가(오른쪽 끝)와 환율은 카드에서 바로 고치고, 맨 아래 줄 **첫 매도 알림**으로 첫 매도 알림을 켭니다. 카드 아래에는 계산 요약 없이 메모만 둡니다. 화면 표시만 바뀌며 저장 필드·알림 규칙은 그대로입니다.
- 분할매도 회차표에는 회차 사이에 지금 시세의 일선·주선·월선 위치를 얇은 줄(예: `--- 80일선 $99.80`)로 표시합니다. 시작 기준가와 종료 기준가 사이에 있는 선을 그 선에 처음 닿거나 넘는 회차(하락 계획은 회차 기준가가 선 이하) 바로 위에 두고, 같은 회차 위의 선은 한 줄에 가까운 순서로 모읍니다. 시작·종료 기준선 자체와 60분봉 N선은 빼며, 바로 아래 회차가 매도 완료면 완료 회차와 함께 접힙니다. 회차는 기존처럼 시작~종료 기준가를 분할 횟수만큼 같은 간격·같은 수량으로 나누고, 선 줄은 화면 표시만이라 회차 가격·수량·체결·알림·저장 기록은 바뀌지 않습니다. 시세가 없으면 선 줄도 없습니다.

- 토큰은 각 기기 브라우저에만 저장합니다. 코드·저장소·메모(온라인 메모장 포함)에 적지 마세요. 그 기기의 GitHub 화면에서 발급해 바로 붙여넣고, 잃어버리면 GitHub의 **Regenerate token**으로 새 값을 받습니다(옛 값은 즉시 무효). 연결할 때 `github_pat_`로 시작하는 fine-grained 토큰만 저장하며 classic 토큰(`ghp_`)은 거부합니다. 브라우저가 토큰을 비밀번호로 저장하자고 하면 저장하지 마세요.
- 데이터 저장소는 반드시 비공개. 공개 저장소면 사이트가 업로드를 거부합니다.
- 기록을 사이트 저장소(`etf-planner`)에 저장하지 마세요. 저장할 때마다 GitHub Pages가 다시 게시됩니다.

## 저장 방식 (`index.html`)

- 입력 즉시 브라우저 `localStorage`에 저장하고, 연결 중이면 잠시 뒤 데이터 저장소의 `etf-planner-data.json`에 올립니다. 저장마다 커밋이 쌓이므로 예전 기록은 그 저장소 커밋 기록에서 봅니다.
- 열 때·45초마다·탭 복귀 시 다른 기기 변경을 확인합니다. 한쪽만 바뀌었으면 자동으로 맞추고, 아무것도 입력하지 않은 새 기기는 저장소 기록을 바로 가져옵니다. 메모·숫자 칸에 입력하는 중이면 다른 기기 기록 적용(자동 병합·충돌 확인 포함)을 칸에서 나올 때까지 미루고 **입력 중 · 끝나면 동기화**로 표시합니다. 이 기기 수정만 올리는 경우는 미루지 않습니다.
- 양쪽 모두 바뀌었어도 서로 다른 칸만 고쳤으면 묻지 않고 합칩니다(계획·알림·재매수 종목은 항목별, 저장소가 지운 계획은 지우고 이 기기가 만든 계획은 남김). 같은 칸이 겹쳤거나(한쪽이 지우고 다른 쪽이 고친 경우 포함) 지난 동기화 기준이 없는 기기면 어느 기록을 쓸지 묻고, **저장소 기록 사용(권장)**이 첫 버튼입니다. 달러선물 보유·정산손익·손절처럼 함께 바뀌는 칸이 겹치면 섞지 않고 한쪽 기록 전체를 고릅니다. 고르기 전에는 자동 업로드를 멈추고 이 기기에만 기록합니다. 덮어쓴 기록은 이 기기에 최근 5개까지 보관하며(저장 공간이 모자라면 오래된 것부터 줄임) **동기화 설정 → 플래너 보관 기록**에서 항목마다 내려받아 **JSON 파일 복원**으로 되돌릴 수 있습니다.
- 올리는 순간 다른 기기가 먼저 저장했다면 덮어쓰지 않고 다시 확인합니다.
- **JSON 파일 복원**은 백업 시각과 계획·달러선물 월물 수를 지금 기록과 함께 보여 주고, 확인해야 바꿉니다. 바꾸기 전 기록은 같은 보관 목록에 남기며, 남기지 못하면 복원하지 않습니다. 바꾼 기록은 연결 중이면 저장소와 다른 기기에도 반영됩니다.
- 토큰이 만료되거나 틀려도 기록은 기기에 남습니다. 동기화 설정에서 새 토큰을 넣으면 이어집니다. 중요한 거래 전에는 **동기화 완료** 표시를 확인하고, 필요하면 **JSON 파일 백업**으로 따로 받아 두세요.

## 화면 모드

- PC(마우스·트랙패드)는 오른쪽 위 화면 모드 버튼에서 **기기 설정 따름**·**밝게**·**어둡게**를 고릅니다. 플래너와 시나리오 페이지가 같은 선택을 쓰고, 그 브라우저에만 저장됩니다(동기화하지 않음).
- 휴대폰·태블릿(터치)은 버튼이 없고 늘 기기 설정(밝은/어두운 모드)을 따릅니다.

## 시세 자동 채우기

- 코스피 200 지수는 종목 코드에 **KS200**을 넣습니다. 한국투자증권 국내 지수 시세로 현재가·일선·주선·월선·60분봉 N선을 수집하며, 긴 N선은 실제 봉이 쌓인 뒤 채워집니다. 추종 ETF를 거래할 때는 실제 ETF 코드를 별도로 넣습니다.
- 월 단위 이동평균선은 화면·휴대폰 알림·알림내역에 **N월선**으로 표시합니다. 시세 파일·기록·알림 규칙의 이름은 기존 그대로 `N개월선`이며, 입력한 월선·달선도 이 이름으로 저장합니다(표시 규칙은 `js/ma-ladder.js` movingLineText).
- 플래너 화면 상단이나 **동기화 설정**의 **시세 즉시 불러오기**를 누르면, 예약 시각을 기다리지 않고 새 시세를 수집한 뒤 데이터 저장소의 시세 파일을 읽어 현재가·기준가·환율과 분할매수 평가액에 반영합니다. 조회 중에는 버튼이 잠기며, 완료·오류와 마지막 수집 시각을 상단에 표시합니다. 별도의 Issues 전용 토큰으로 수집 저장소에 요청 ID만 담은 이슈를 만들며, GitHub 작업 시작·수집이 끝날 때까지 잠시 대기할 수 있습니다. 최근 추가한 종목의 저장 대기 기록을 먼저 동기화하고 수집합니다. 요청한 수집 결과를 약 5분까지 기다리며, 실패·지연 시 마지막 시세를 유지하고 안내합니다. 예약 수집 주기는 그대로입니다. GitHub 예약 실행이 빠지거나 크게 늦어 마지막 수집이 오래되면(평일 10:20~15:20은 70분, 그 밖은 7시간 30분 초과) 플래너·자산현황 상단의 수집 시각 옆에 **수집 지연**을 주황색으로 표시합니다.
- 동기화를 연결하면 데이터 저장소의 `etf-planner-prices.json`(별도 수집 저장소 Actions **KIS 시세 수집**이 갱신)을 함께 읽어 채웁니다. 읽기만 하고, 바뀌지 않았으면 다시 받지 않습니다(ETag).
  - 분할매도: 종료 기준선이 `60일선`·`20주선`·`25월선`처럼 N일선·N주선·N월선인 종료 기준가(국내 종목은 원화, 미국 종목은 달러 계획만). 시작 기준가(첫 매도 기준가)는 수정 창의 시작 기준선이 ‘직접’(기본)이면 직접 정하고, 일선·주선·월선을 고르면 종료 기준가처럼 채웁니다. 현재 가격은 설명 줄에 표시만 합니다.
    - 종료 기준선은 수정 창에서 숫자와 일선·주선·월선으로 고르고, 바꾸면 종료 기준가가 바로 바뀝니다. 시세 파일에 아직 없는 기준선은 함께 받은 종가로 같은 규칙(종가 단순이동평균)으로 계산하고, 봉이 모자라면 다음 수집 뒤 채워집니다.
    - 평가액은 보유 수량 × 현재가(달러 계획은 × 환율)로 계산해 화면에만 표시합니다(계획 화면은 남은 수량 기준). 수량 없이 평가액만 넣은 계획은 넣은 값을 씁니다.
    - 수정 창의 **매도 비중 (%)**(기본 100%)을 낮추면 보유 수량의 그 비중만 회차에 나눠 팔고 나머지는 남깁니다. 수량은 1주(비트코인은 0.00000001 BTC) 단위로 내림하고, 평가액만 넣은 계획은 평가액의 그 비중을 나눕니다.
    - 회차마다 같은 수량을 팝니다. 평가액만 넣은 계획(여러 추종 ETF처럼 주수로 넣기 어려운 경우)도 평가액을 저장할 때의 종목 시세로 수량을 환산해 같은 수량씩 나누므로, 회차 금액은 회차 기준가에 비례해 줄어듭니다. 저장할 때 시세가 없었거나 예전에 넣은 평가액은 첫 매도 기준가로 환산하고, 평가액을 다시 넣어 저장하면 그때 시세로 바뀝니다.
  - 분할매도 달러 계획 환율: 한국투자증권의 USD/KRW 현물 환율(`fx.USDKRW`). 달러선물 보유와 관계없이 원화 환산·평가액에 씁니다. 정규 수집과 **한국·미국이 모두 개장하는 거래일의 18:10~22:10, 30분 간격 추가 수집**(하루 9회)에서 갱신되며, 은행·증권사의 실제 환전 적용 환율과는 다를 수 있습니다. 조회 실패 시 마지막 현물 환율을 유지하고, 현물 환율이 아직 없으면 계획의 마지막 환율을 그대로 둡니다.
  - 달러선물: 보유 근월물(계약 수가 있는 가장 가까운 월물, 손절로 보유를 모두 팔았으면 마지막 손절 월물이며 그 월물의 셋째 월요일(최종거래일)부터는 다음 월물)의 시선·일선·주선·월선 구간 기준가와 아직 안 산 계약의 3등분 매수가. 현재가는 달러선물 화면 제목 아래에 크게 표시만 합니다(현물 환율 아님). 야간 거래 중에는 보유 월물의 야간시장 현재가를 별도로 받고, 일·주·월선과 N선은 기존 주간 봉을 기준으로 유지합니다. 한국·미국이 모두 개장하는 거래일 18:10~22:10에도 30분마다 현재가를 갱신합니다. 시세 파일에 체결 시각이 없어 수집 시각(한국 시간)과 경과 시간을 함께 보이며, 실시간 시세가 아니므로 수집 후 1시간이 지나면 ‘지연’을 붙입니다. 휴장·장 마감 뒤에는 기준일 종가, 조회 실패 시에는 마지막 가격과 기준일을 경고색으로 표시합니다. 화면을 열 때 시세를 따로 조회하지 않고, 보유 월물과 손절 기록이 모두 없으면 수집 대상이 없어 안내만 표시합니다.
  - 재매수: 종목마다(왼쪽 **재매수 종목** 목록, **＋ 추가**) **종목 이름 옆 연필 → 종목 코드**를 넣으면(국내 종목 코드 또는 미국 종목 심볼) 현재가와 `25일선`~`150일선`, `25선`~`150선`(60분봉 차트의 25~150 이평선) 단계 기준가. N선은 수집 작업이 한국투자증권 분봉으로 60분봉을 만들어 계산하며, 처음에는 과거 봉을 몇 번의 수집에 나눠 받아 짧은 N선부터 채워집니다(그 전에는 직접 넣은 값 유지). 미국 종목은 가격·금액·보유 금액이 달러입니다. 비운 단계는 앞뒤 가격 사이를 고르게 나눈 추정치(≈)를 표시만 합니다(실제 이평선 값이 아니며 배분·알림에는 쓰지 않음). 옛 이름 `25분봉` 등은 `25선`으로 보이고 처음 고칠 때 바뀝니다. 새 종목 코드는 다음 수집(평일 장중 30분마다) 뒤 채워집니다. 기준 입력에서 직접 넣는 값은 신저점 가격뿐이며, 현재가는 시세로 채우는 읽기 전용 칸입니다.
- 비트코인: 시세 파일에 `BTC-USD`(Coinbase 달러 시세, 키 없음)가 늘 들어 있습니다. 수집 작업이 정규 국내·미국장 수집 때마다 함께 받고, **한국·미국이 모두 개장하는 거래일의 18:10~22:10에는 30분마다 현물 환율·보유 야간 달러선물과 함께** 받습니다(한국시간 18:10·18:40·19:10·19:40·20:10·20:40·21:10·21:40·22:10). 한국·미국 휴장일과 한국 야간 특별휴장에는 이 추가 수집을 건너뛰고, 주말 비트코인 전용 수집은 기존 3시간 간격을 유지합니다. 일봉은 UTC 0시 기준이고 주봉(월~일)·월봉은 그 일봉을 묶어 만듭니다.
  - **동기화 설정** 창의 시세 줄에 비트코인 현재가(달러)와 기준일을 보여 줍니다.
  - **알림 → 직접 추가 알림**에서 종목 코드에 `BTC-USD`를 넣으면 다른 종목처럼 N일선·N주선·N월선 알림을 받습니다(`BTC`는 미국 ETF 심볼이라 비트코인이 아님).
  - **분할매도**에서 종목 코드에 `비트코인` 또는 `BTC-USD`를 입력하면 통화를 **달러(USD)**로 자동 선택·고정하고, 현재가·자동 기준선·평가액과 연결 알림에 같은 비트코인 시세를 씁니다. `비트코인`으로 입력한 코드는 저장할 때 `BTC-USD`로 바꿉니다(`BTC`는 미국 ETF 심볼).
  - 비트코인 보유 수량은 소수점 8자리까지 입력하며, 회차별 수량을 0.00000001 BTC 단위로 균등 배분합니다. 합계는 보유 수량과 같고, 완료 체크 후 남은 수량도 같은 단위로 계산합니다. 주식은 기존처럼 정수 주수로 배분합니다.
  - 재매수 칸은 국내·미국 종목만 시세로 채웁니다(비트코인 제외).
- 시세가 우선입니다. 직접 고친 값은 그 칸의 시세가 다음에 바뀔 때 덮어씁니다(마지막으로 채운 값은 기록의 `auto`에 둠).
- 시세 기준일은 작게 표시하고, 3일 넘게 지났거나 마지막 조회에 실패했으면 주황색으로, 3일 넘게 지났으면 경고를 보여 줍니다. 수집 상태는 **동기화 설정** 창 아래에서도 봅니다.

## 달러선물 자동 분할매수

달러선물의 **분할매수 → 연필 → 시작·종료 기준으로 자동 배분**에서 시작기준선, 종료가격, 총 매수 계약 수를 입력합니다. 종료가격은 기존 **직접 가격 입력** 또는 **이동평균선 선택**으로 정하며, 이동평균선은 시선(60분봉)·일선·주선·월선과 기간(1~400)을 고릅니다. 기존 시세의 이동평균 값 또는 함께 받은 일·주·월 종가로 계산하며, 없는 시세를 위해 API나 자동 수집을 추가하지 않습니다. 배분할 시선·일선·주선·월선을 선택하면 사용할 회차와 회차별 계약 수를 미리 보여 줍니다. 저장한 카드에는 시간축별 마지막 기준선·분할 횟수·계약 수와 가격순 매수 회차를 표시합니다. 종료가격은 마지막 매수 기준이며 기존 보유분의 청산 조건이 아닙니다.

총 계약 수는 이 분할매수 계획의 완료 계약을 포함하며, 별도로 입력한 보유 월물은 포함하지 않습니다. 새 시세가 오면 완료 계약의 체결가·월물·알림을 유지하고 미매수 계약만 다시 배분합니다. 다 산 회차도 간격 계산에 넣으므로 회차를 체결해도 시세가 같으면 남은 회차의 가격·계약 수는 처음 계획 그대로이고, 이동평균이 움직이면 같은 회차의 가격이 그 선을 따라 움직입니다. 시작선 시세가 없거나 시작 기준가가 종료가격보다 높아지면 추가 매수를 기다립니다. 기존 직접 설정 계획은 그대로 열리고, 자동 배분으로 바꾸거나 다시 **기준선별 직접 설정**으로 수정할 수 있습니다.

이동평균 종료 방식을 선택한 계획은 종료선 가격이 바뀌면 미완료 계약만 다시 배분하며, 완료 계약과 직접 수정 가격·월물·알림은 유지합니다. 종료가가 시작가 이하이거나 직접 수정 가격이 범위를 벗어나면 기존 회차를 보존하고 경고하며 추가 매수 체크·알림을 중지합니다. 종료선 시세가 아직 없으면 새 계획을 저장하지 않습니다. 직접 입력 방식과 기존 기록에는 이 동작을 적용하지 않습니다.

## 달러선물 신저점 손절 후 재매수

- 손절은 특수한 상황이라 평소에는 실행 전·진행 중·완료 모두 달러선물 화면 위에 **한 줄로 접어** 상태만 보여 줍니다(기준 미입력·실행 전·신저점 이탈·손절 진행 중·재매수 대기·진행 중·완료와 다음 손절·재매수 환율, 실행 뒤에는 보유 계약. 폰 한 줄에 들도록 회차·현재 환율은 펼친 화면에서 봅니다). 손절·재매수 시점이 되거나 보유 미반영·체결 초과 경고가 새로 생기면 자동으로 펼치고, 접힌 줄이나 펼친 제목(왼쪽 화살표)을 눌러 펼치고 접으며, 고른 상태는 다음에 새 매매 시점이 올 때까지 유지합니다. 기준은 펼친 뒤 제목 옆 연필로 입력합니다. 펼친 상태는 저장하지 않습니다(페이지를 새로 열면 다시 접힘).
- **달러선물 → 신저점 손절 후 재매수** 제목 옆 연필(손절 기준 수정 창)에서 신저점 환율·손절 하단·이탈 전 계약 수·**손절 비중 (%)**·분할 횟수를 넣고 저장합니다. 바꾼 칸만 저장하며, 보유 근월물 시세가 없으면 현재 환율도 이 창에서 넣습니다. 손절 비중은 0~100%로 직접 바꾸며, 기존 기록과 비운 입력은 기본 50%를 사용합니다. 손절 목표의 소수점 이하는 내림하고, 회차는 목표 계약 수 이하로 줄입니다. 신저점부터 하단까지 고르게 나누며, 한 회차뿐이면 하단에서 손절합니다. 0%면 손절 회차가 없습니다.
- **손절 하단**은 숫자 옆 단위에서 **원**(직접 가격) 또는 **일선·주선·월선**을 고릅니다. 선을 고르면 숫자는 기간(1~400)이고, 보유 근월물 시세로 그 선의 값을 하단으로 채웁니다(창 아래 작은 글씨에 지금 값 표시). 시세가 바뀌면 체크한 손절은 그대로 두고 남은 회차만 새 하단으로 다시 나누며, 알림은 같은 이력을 이어 갑니다. 선의 시세가 아직 없거나 하단이 신저점 환율 이상이면 손절 회차와 알림을 멈추고 접힌 줄·보유 계약 카드에 이유를 보여 줍니다. 보유 근월물의 봉(상장 후 기간)보다 긴 선을 고르면 창 아래와 카드에 **계산 불가 · N월선까지**처럼 고를 수 있는 가장 긴 선을 알려 줍니다. 하단을 채운 뒤 그 선의 시세가 빠지면(상장 기간이 짧은 새 월물로 바꾼 경우 등) 마지막 하단 값으로 손절 회차와 알림을 이어 가고, 기준 줄과 창 아래에 **시세 없음 · 마지막 값**을 주황색으로 표시합니다. 단위를 다시 원으로 바꾸면 마지막 하단 값을 직접 하단으로 남기며, 고른 선은 `futures.rebuy.floorLine`(월선은 기존 이름 `N개월선`)에 저장합니다.
- 이탈 전 계약 수는 처음 입력할 때 고정합니다. 실제 손절 후 보유 월물을 수정해도 손절 목표는 바뀌지 않습니다. 손절을 체크하면 예정 수량·환율이 기록되므로 실제 체결 수량·환율로 맞추세요. 재매수 시작 전에는 손절을 체크한 뒤에도 ETF 재매수처럼 신저점 환율·손절 하단·이탈 전 계약 수·손절 비중·분할 횟수를 바꿀 수 있습니다. 체크한 손절의 계약 수·환율은 그대로 두고 남은 회차만 새 기준으로 다시 나누며, 손절 목표(이탈 전 계약 수 × 비중)는 이미 손절한 계약 수 이상이어야 합니다. 재매수 시작 뒤 손절 기준은 재매수 체크를 모두 해제한 뒤 변경합니다.
- **1. 분할 손절** 표는 분할매도 회차표와 같은 모양입니다(회차 · 손절 환율 · 계약 · 체결 · 알림). **체결** 칸에 그 회차에서 실제 판 누적 계약 수를 넣으면 체결한 계약만 보유·누적 정산손익에 반영하고, 계획보다 적으면 **부분 체결**(체크 '−', 회차 아래 '남은 N')로 남은 계약을 같은 회차에 둡니다(알림도 이어짐). 체크는 남은 계약까지 회차 환율로 완료하고, 0으로 고치거나 체크를 풀면 기록을 지웁니다. 회차마다 한 줄이며, 체결한 회차의 손절 환율 칸은 실제 체결 환율(점선)이라 눌러서 그 자리에서 고칩니다. 반영한 월물은 **손절 완료** 띠에 모아 보여 주고(완료 회차는 이 띠로 접음), 기록한 월물이 지금 보유에 없거나 보유에 반영하지 못한 회차만 환율 아래에 작은 주황 글씨로 표시합니다. 부분 체결은 `partial`·`plannedQty`로 그 회차에만 저장하고, 이 필드가 없는 기존 기록은 완료로 읽습니다.
- **재매수**는 평균 손절 환율을 기준으로 하는 기존 반등 단계 방식을 유지합니다. ETF 재매수 화면의 가격 제한 해제와 별개이며, 상세 계산 규칙은 [js/rebuy.js](js/rebuy.js)의 `futureRebuySummary`·`rebuyPlanned` 주석을 참고하세요. 회차를 체크하면 회차 환율로 기록하며, 부분 체결은 체크 후 실제 계약 수·체결 환율로 수정합니다. 계약 수를 계획보다 적게 고치면 손절 표처럼 **부분 체결**(체크 '−', 회차 아래 '남은 N')로 남은 계약을 같은 회차에 두고 알림도 이어지며, 체크하면 남은 계약까지 완료합니다(`buys[t].partial`·`plannedQty`, 입력 때만 저장). 산 회차도 배분 순서에 넣으므로 회차를 체결해도 남은 회차의 환율·계약은 처음 계획 그대로입니다. **2. 반등 단계별 재매수** 표도 분할 손절 표와 같은 회차마다 한 줄입니다(단계·회차 · 재매수 환율 · 계약 · 체결 · 알림). 배분한 회차가 있는 단계만 표에 두고, 단계 첫 회차 줄의 환율(점선)이 그 단계 기준 환율이라 눌러서 고치며 알림도 그 줄에서 켭니다. 평균 손절 환율 위 회차는 흐린 '제외' 줄, 산 회차는 환율 칸에서 체결 환율을, 체결 칸에서 계약 수를 고칩니다. 반영한 월물은 **재매수 완료** 띠에 모으고(산 회차는 이 띠로 접음), 배분 없는 단계와 첫 회차를 산 단계의 기준 환율·알림은 맨 아래 **다른 단계** 띠를 펼쳐 고칩니다. 재매수 월물은 따로 고르지 않고 체크할 때 근월물(보유가 없으면 마지막 손절 월물, 그 최종거래일부터는 다음 월물)에 넣습니다.
- **2. 반등 단계별 재매수 → 제목 옆 연필**에서 분할매수처럼 시작 기간과 시간선(60분봉)·일선·주선·월선, **종료 기준(직접 가격·시선·일선·주선·월선)**을 고르고 회차·환율·계약 수를 미리 봅니다. 예를 들어 **50시간선**을 저장하면 이전 미체결 단계는 제외하고 그 선부터 남은 계약을 다시 배분하며, 재매수 시점과 알림도 같은 계획을 따릅니다. 종료 기준에서 직접 가격을 고르면 그 가격을, 평균선을 고르면 해당 선의 시세와 도달 회차를 마지막 기준으로 사용합니다. 평균 손절 환율 자동 기준도 선택할 수 있습니다. 시작·종료선의 시세가 없으면 해당 시세가 채워질 때까지 기다립니다. 기존 체결·보유·누적 정산손익과 다른 선물 설정은 유지합니다. 시작선·종료가격은 `futures.rebuy.startLine`·`endLine`·`endPrice`에 저장되어 새로고침·백업·동기화 후에도 유지됩니다. 선택한 시작선의 시세가 없으면 앞 단계로 대체하지 않고 시세가 채워질 때까지 기다립니다.
- 재매수를 시작하면 남은 손절은 멈추고, 판 계약 수까지만 재매수합니다. 계약 수를 복원하는 계획이며 선물 매도 대금을 현금 재매수 예산으로 계산하지 않습니다. 예전 '손절 환율 복귀' 방식으로 체크한 재매수는 첫 미완료 반등 단계에 합쳐 보여 주고, 처음 고칠 때 그 단계 기록으로 옮깁니다.
- 설정·체결 기록·알림은 `futures.rebuy`로 기존 비공개 동기화·JSON 백업에 포함됩니다. 화면을 보기만 하면 새 필드를 만들지 않습니다. 보유 근월물의 현재 환율·일선·N선(60분봉, 한국투자증권이 묶은 08:45 기준 60분봉) 기준가와 손절 하단선은 기존 시세 파일로 채우며(현재 환율은 화면 맨 위와 보유 계약 카드에 표시하고, 보유 근월물 시세가 없을 때만 손절 기준에서 직접 넣습니다), 신저점과 하단선을 고르지 않은 하단은 직접 정합니다.
- **보유 반영**: 손절을 체크하면 판 계약 수 이상 남은 가장 가까운 보유 월물에서 계약을 빼고(남은 계약의 단순평균가는 그대로), 실현 손익 (체결 환율 − 단순평균가) × 계약 × 1만 원을 누적 정산손익에 더합니다. 그래서 **보유·계산 기준**, 목표 환율 기대수익, 환율 도달 시 손익, 월물교체 예상, 계획 전부 체결 가정이 바로 바뀝니다. 재매수를 체크하면 근월물(보유가 없으면 마지막 손절 월물, 그 최종거래일부터는 다음 월물)에 체결 환율로 편입해 단순평균가를 가중평균합니다. 체크 후 실제 계약 수·체결 환율을 고치면 보유·누적 정산손익도 함께 고쳐지고, 체크를 풀면 기록한 월물로 되돌립니다(확인 창). 손절 계약을 늘리면 기록한 월물(모자라면 늘린 계약 수만큼 남은 가장 가까운 월물)에서 그 월물 단순평균가로 빼고, 다른 월물에서 뺐으면 기록에 월물별 판 계약·단순평균가(`legs`)를 남깁니다. 줄이거나 체크를 풀면 마지막에 판 월물부터 그 월물의 판 시점 단순평균가로 되돌립니다. 기록한 월물이 지금 보유에 없으면(월물교체·손절로 모두 판 월물) 손절 표에 **(월물) 보유 없음**으로 표시하고, 줄이거나 풀 때 그 월물을 되살릴지, 보유는 그대로 두고 기록·누적 정산손익만 고칠지(월물교체, 보유는 직접 수정) 차례로 묻습니다.
- 반영한 월물·판 시점 단순평균가는 손절·재매수 기록의 `month`·`settlementPrice`에 저장합니다. 이 연동 전에 체크했거나 한 월물에 판 계약 수만큼 보유가 없어 반영하지 못한 기록은 **보유 미반영**으로 표시하고 계산에 넣지 않습니다. 계좌 기준으로 직접 고치지 않았다면 **보유 월물에 반영**을 눌러 바뀔 보유 계약 수·누적 정산손익을 확인하고 반영합니다(이미 직접 고쳤다면 누르지 않습니다).
- 회차·재매수 가격 옆에서 알림을 켤 수 있습니다. 실제 주문은 증권사에서 실행합니다.

## ETF 손절 후 재매수 단계 편집

- 손절 예정 수량이 0주인 미체결 회차는 보유 띠·손절 표·진행 회차 수에서 건너뜁니다. 다음 손절·재매수 표시는 남은 칸에 맞추며, 원래 회차 번호·가격과 체결 기록은 유지합니다.
- 화면은 **달러선물 신저점 손절 후 재매수**와 같은 구조입니다. 종목 제목 아래 손절 기준 한 줄(**신저점 가격 · 하락 간격마다 회당 손절**, 연필)을 누르면 손절 기준 수정 창에서 신저점 가격·하락 간격·회당 손절·표시 회차를 고치고 **저장**합니다(바꾼 칸만 저장, 현재가·이탈 전 보유는 읽기 전용). 그 아래 **보유 주수** 카드(보유 / 이탈 전 주수, 제목 옆 칩은 손절·재매수 시점일 때만)는 1칸 = 손절 1회(표시 회차)로, 1회 칸이 오른쪽 끝입니다. 손절한 만큼 칸이 비고 재매수 주수는 가장 최근에 비운 칸부터 파랑으로 다시 채우며, 말풍선이 다음 손절(재매수를 시작하면 다음 재매수)을 가리키고 시점이면 주황입니다. 카드 아래 두 줄은 손절 도달 기준(절반·전액 매도의 하락률·가격·회차)입니다.
- **1. 분할 손절**·**2. 반등 단계별 재매수** 표는 달러선물과 같은 회차표(회차 · 가격 · 수량 · 체결 · 알림)이고, 기본으로 펼쳐 둡니다. 접은 상태는 화면 상태로만 유지하고, 다른 회차가 새로 손절·재매수 시점이 되면 다시 펼칩니다. 손절 표는 끝나지 않은 가까운 5회만 바로 보이고 나머지는 **남은 손절** 띠, 배분 없는 단계와 첫 회차를 산 단계의 기준가·알림은 **다른 단계** 띠를 펼쳐 고칩니다. 체결한 회차의 가격과 단계 기준가는 점선 글자를 눌러 그 자리에서 고칩니다.
- **2. 반등 단계별 재매수** 제목 옆 연필은 단계 편집 창을 엽니다. 분할매수·분할매도처럼 **시작 평균선 → 마지막 평균선**을 정하고 마지막 선의 매수 회차·재매수 비중·가격 도달 조건을 수정하고 **저장**으로 적용합니다. **취소**는 원래 설정을 유지합니다.
- **평균선 단계**에서 시간축을 고르고 시작·마지막 선을 바꿔 범위를 추가하거나 줄입니다. 범위 밖의 다음 평균선은 마지막 회차 가격 계산에만 쓰며 새 매수 수량을 배정하지 않습니다. 기존 평균선·단계별 설정·체결 기록은 삭제하지 않습니다.
- 평균 손절가 계산·표시는 유지합니다. 편집 창에 설정한 마지막 선은 최대 범위이며 실제 종료선·회차와 배분을 미리 보여 줍니다. 실제 마지막 선의 2·3회차 가격도 직접 수정할 수 있습니다. 범위를 따로 저장하지 않은 기록은 기존 마지막 단계 선택을 유지합니다.
- **재이탈**: 재매수를 시작해도 남은 손절 회차는 그대로 보이고 체크·알림할 수 있습니다. 남은 손절가는 이미 손절한 가격보다 낮아 가격이 다시 내려가야 닿습니다. 재매수를 시작한 뒤의 손절 수량은 그때 보유(이탈 전 보유 − 손절 + 재매수)의 회당 비율로 나누고, 손절 합계 한도도 재매수 수량만큼 늘어납니다. 재이탈 손절을 기록한 뒤 그 재매수를 하기 전까지는 재이탈 직전 보유를 기준으로 유지합니다. 손절 도달 기준(절반·전액 매도)은 재매수 전에는 이탈 전 보유 계획 기준이고, 재매수 뒤에는 같은 기준 보유의 절반·전부를 이미 판 손절과 남은 회차 수량으로 처음 넘기는 회차로 다시 계산합니다(이미 넘었으면 도달로 표시).
- 재매수 뒤 새 손절을 기록하면 그때까지 산 마지막 평균선과 회차를 함께 저장하고, 이후 재매수는 그 다음 회차부터 같은 평균 손절가 규칙으로 배분합니다. 예: 25·32·42선을 다 산 뒤 재이탈하면 25·32·42선 가격이 다시 와도 사지 않고 60선부터, 32선 1회차까지만 산 뒤 재이탈하면 32선 2회차부터 삽니다. 다음 선이 범위 상한 밖이면 그 선 하나에, 다음 선이 없으면 새로 배분하지 않습니다. 이번 범위는 재이탈 뒤 첫 재매수 때 고정하고, 그 손절 기록을 지우면 이전 계획으로 돌아갑니다. 달러선물 재매수는 기존처럼 재매수를 시작하면 남은 손절을 멈춥니다.
- 설정·체결·부분 체결·손절 기록은 기존 저장·동기화·JSON 백업에 포함됩니다. 화면을 열거나 복원할 때 새 선택 필드를 저장하지 않습니다.
- 상세 배분·회차·옛 고정 계획 호환 규칙은 [js/rebuy.js](js/rebuy.js)의 `etfRebuyPlan`·`etfTrancheLevels`·`weightEtfRebuyTranches`·`rebuySummary` 주석을 참고하세요. 실제 주문은 증권사에서 실행합니다.

## 휴대폰·PC 매매 기준 알림

- 휴대폰·PC 알림과 알림내역은 종목 코드 대신 종목명을 보이고(분할매도 카드 이름 → 계획 이름 → 자산 배분·재매수의 같은 코드 이름, 못 찾으면 코드), 같은 이름이 다른 코드에도 있으면 코드를 함께 붙입니다. 알림 제목 앞에 **분할매도·분할매수·재매수·달러선물·이동평균선** 종류를 표시합니다. 분할매도·분할매수 목록과 제목도 카드 이름이 없으면 종목명을 보이고(재매수는 기존처럼 종목 이름), 저장된 카드 이름·종목 코드·알림 조건은 바꾸지 않습니다.
- 오른쪽 위 **알림**에서 기능 적용 이후 발생한 알림을 최신순으로 확인합니다. 종목명·발생 시각·구체적인 조건·당시 가격·기준값을 보관하며, 알림을 누르면 기존 종목 이동 기능으로 연결됩니다. **전체/읽지 않음**, 읽음 표시, 개별/전체 삭제를 지원합니다. 같은 회차의 재알림은 최초 알림 항목에 합쳐지며, 읽은 뒤 재알림이 또 오면 다시 읽지 않음으로 표시합니다. 설정은 내역 화면의 **알림 설정**에서 엽니다.
- 내역과 읽음·삭제 상태는 기존 플래너 JSON 백업·복원 및 비공개 동기화에 포함됩니다. 새 발송 이력은 기존 `etf-planner-alert-state.json`에 원자적으로 기록하고, 플래너에 저장된 이벤트는 그 파일에서 정리합니다. 앱을 닫은 동안 받은 푸시도 브라우저 수신함에 보관합니다. 수신 재시도는 이벤트 ID로 중복을 제거하며 삭제한 내역을 다시 만들지 않습니다. 이전의 평가·발송 대기를 과거 내역으로 생성하지 않습니다.

- 각 화면의 가격 옆 **알림 ON/OFF**로 기존 기준을 켭니다. 분할매도 첫 매도·회차별 매도, 분할매수 돌파 회차·목표가(회차 가격 이상), 매수대기(선택한 이동평균선 이하), 기존 직접 입력 회차(계획 방향을 따름), 달러선물 선별 도달·2·3차 매수, 재매수 신저점 이탈·회차별 손절·단계별 재매수(단계 안 1·2·3차)를 연결하며, 종류별 **전체 ON/OFF**도 있습니다. 첫 매도와 1회차는 같은 설정입니다.
- 알림 기준가는 계획 수정과 새 시세에 따라 자동 반영됩니다. 완료 회차·단계와 재매수가 시작된 뒤의 신저점 이탈은 제외합니다. ETF 재매수의 남은 손절 회차는 재매수 중에도 알립니다(달러선물은 재매수를 시작하면 남은 손절을 제외). 재매수 단계 알림을 켜면 그 단계의 1·2·3차 회차 가격을 모두 알립니다. 재매수 단계는 실제 배분 금액과 입력된 기준가가 있는 경우만 발송하며 빈 가격의 추정값은 사용하지 않습니다.
- 분할매도 **전액매도**의 휴대폰·PC 알림은 기존 **첫 매도(1회)·회차별 매도** 알림을 그대로 씁니다(계획 진행 카드 맨 아래 **첫 매도 알림** ON/OFF). 새 알림 라벨은 없습니다.
- 계획 외의 기준선은 **알림 → 직접 추가 알림 (선택) → 추가**에서 별도 등록합니다. N일선·N주선·N월선과 근접 허용 범위(기본 ±0.5%)를 저장하며 매매 계획 없이 알림만 등록한 종목도 수집합니다. 비트코인은 종목 코드에 `BTC-USD`를 넣습니다.
- 동기화가 연결된 안드로이드 휴대폰이나 PC(Chrome·Edge·Firefox·Safari)에서 **알림 → 알림 받기**를 한 번 누르고 브라우저 알림을 허용하면, 사이트를 닫아도 웹 푸시를 받습니다. 휴대폰과 PC를 함께 연결하면 같은 알림이 둘 다에 옵니다. 각 기기에서 따로 연결하고 **이 기기 알림 해제**로 해제합니다.
- 도착한 알림을 누르면 알림의 ID로 해당 계좌·종목의 분할매도·분할매수·재매수 화면이나 달러선물 화면을 엽니다. 완료 회차의 접기·펼치기 상태는 그대로 두고(알림은 미완료 회차에만 옵니다), 한 줄로 접힌 달러선물 손절·재매수 영역만 펼친 뒤 종목까지 스크롤하고 3초간 강조합니다. 기록 복원·화면 로딩·백그라운드 복귀가 끝난 뒤 이동합니다. 직접 추가한 기준선 알림은 해당 규칙을 펼칩니다. ID가 없는 옛 알림은 코드가 유일한 종목이나 규칙만 찾으며, 삭제된 ID나 중복 코드는 다른 계좌로 대체하지 않습니다. 기존에 연결한 기기는 플래너를 한 번 열면 새 이동 기능이 적용됩니다.
- PC는 보통 브라우저가 켜져 있을 때 받고(플래너 탭은 닫아도 됨), 꺼져 있던 동안의 알림은 다시 켤 때(최대 24시간) 옵니다. Windows에서 브라우저를 닫아도 받으려면 Edge로 연결하고 Edge 설정 → 시스템 및 성능의 ‘닫혀 있을 때 백그라운드 확장 및 앱 계속 실행’을 켜 둡니다(Windows 10 20H1 이상). Chrome은 창을 모두 닫으면 꺼질 수 있습니다. Windows·Mac 알림 설정이나 방해 금지(집중 모드)에서 브라우저 알림이 꺼져 있으면 보이지 않습니다.
- 비공개 데이터 저장소의 시세 수집 작업이 화면과 같은 `prices.js`·`rebuy.js`·`trade-alerts.js`로 기준가와 배분을, `assets-calc.js`로 분할매수 회차 알림(자산 기록 `etf-planner-assets.json`)을 계산합니다. 매도·손절은 기준가 이하, 달러선물 이동평균선 매수·재매수는 기준가 이상, 신저점 이탈은 기준가 미만에서 한 번 알립니다. 가격이 반대편으로 돌아왔다가 다시 도달하면 다시 알립니다. 켰을 때 이미 조건에 해당하면 다음 수집 때 한 번 알립니다.
- 별도로 추가한 이동평균선 알림은 허용 범위 진입이나 위아래 통과를 감지하며 같은 범위에 머무는 동안 반복하지 않습니다.
- **미완료 매매 재알림**: 연결 알림의 회차를 완료 체크하기 전이고 그때 시세가 여전히 같은 조건이면 한국 시간 기준 최초 알림 다음 날 오전 9시~오후 8시 1회, 이틀 뒤부터 매일 오전 9시~12시·오후 2시~8시 각 1회 다시 알립니다(최초 알림 당일·오후 8시~다음 날 오전 9시·낮 12시~2시는 없음). 별도 설정 없이 적용되며, 회차 알림을 꺼 둔 매매 회차도 도달 뒤 체결하지 않았으면 도달 알림 없이 재알림만 받습니다(같은 종목·매매 종류는 한 건으로 묶음). 완료 체크·계획 삭제·기준 수정으로 끝나며 알림 OFF로는 멈추지 않습니다. 알림을 읽기만 해서는 멈추지 않습니다. 자세한 기준은 [기준선 알림 안내](docs/moving-average-alerts.md#미완료-매매-재알림)에 있습니다.
- 미국 ETF를 추종하는 국내 ETF를 거래한다면 **알림 → 미국 기준 한국장 재알림**을 켭니다(기본 OFF). 밤사이 발생한 미국 종목 신호만 한국장 **오전 9시 45분쯤**에 기준별 한 번 더 받습니다. 새 신호가 없으면 보내지 않으며 OFF·삭제·완료 처리한 기준은 제외합니다. 주말·휴장일은 건너뛰고, 재알림에는 신호 당시 미국 시세를 표시합니다. 예약 실행이 늦어질 수 있습니다.
- 국내 주식·ETF는 **09:20부터 15:20 전까지** 알립니다. GitHub 예약 실행이 보통 25~35분 늦게 시작해(10월 실측 13~41분) 국내 장중 수집 12회를 미리 당겨 두었습니다. 첫 조회는 보통 09:45쯤, 이후 약 30분마다, 마지막 조회는 41분 늦어도 15:10 전에 시작합니다. 09:20 전·15:20 이후에 시작한 국내 장중 실행은 건너뜁니다. 16:40 종가 수집은 이동평균·평가액 갱신용으로 유지하며 국내 주식 알림은 보내지 않습니다. 국내 알림 재시도도 15:20에 끝납니다.
- 미국 장중 1시간 20분(23:10~03:10, 그 뒤는 06:40 마감 값) 수집 기준이며(비트코인은 거래일 저녁 18:10~22:10에 30분마다, 주말에는 3시간마다) GitHub 예약 실행이 늦어질 수 있습니다. 수집 사이에 닿았다가 돌아오는 움직임은 놓칠 수 있습니다. 오래된 시세·조회 실패·봉 부족에는 새 알림을 만들지 않습니다. 달러선물은 주식과 거래 시간이 달라 국내 주식 알림 시간 제한을 적용하지 않습니다.
- 발송키는 기존 수집 환경에서 생성해 암호화해 보관합니다. 새 외부 서버나 텔레그램 계정은 필요 없습니다. 알림에는 종목·선·가격만 담고 보유 수량·손익·계좌정보는 넣지 않습니다. 발송 서버는 내용을 만들며 휴대폰의 잠금화면·PC 알림 센터에도 표시될 수 있습니다.
- 설정·기기 구독은 기존 비공개 기록에 저장합니다. 구독 정보도 개인 기록이므로 공개 저장소에 복사하지 마세요. 이전 버전의 플래너를 켜 둔 기기는 새로고침한 뒤 수정하세요.
- 자세한 연결·판정·복구 방법은 [기준선 알림 안내](docs/moving-average-alerts.md)에 있습니다.

## 시나리오 가정 저장 (`valuation.html`)

- **원·달러**에서는 한미 GDP·M2의 같은 분기 전년 대비로 상대 통화압력을 계산하고, 5·10년 추이와 실제 환율·과거 관계를 비교합니다. 공식 자료가 없는 값은 계산하지 않습니다. 한국 M2 개편 기준 연결·예약 수집·검증 한계는 [통화강도 안내](docs/currency-pressure.md)를 참고하세요.

- 가정을 바꾸면 브라우저에 바로 저장되고 다시 열면 복원됩니다. **가정 저장** 창에서 이름 붙여 저장·불러오기·삭제합니다(같은 이름 덮어쓰기, 저장 안 한 조정값이 있을 때 다른 저장본 불러오기·**모든 가정 기본값으로**는 먼저 확인).
- 기본값과 다른 입력만 저장합니다. 바꾸지 않은 기준 종가·시총 등은 페이지 기준 자료가 갱신되면 새 값을 따릅니다.
- AI 구독사업은 연평균 결제계정 기준으로 부가세·수수료·추론비·기타 비용·연 고정비를 차감합니다. 원가 프리셋과 영업가치 가정도 같은 저장·동기화를 사용합니다. 기준과 해석은 [AI 구독사업 시나리오](docs/ai-subscription-scenario.md)에 정리했습니다.
- 기기 간 동기화는 따로 설정할 필요가 없습니다. 메인 플래너를 연결한 기기는 같은 저장소 이름·토큰을 읽어, 같은 데이터 저장소의 `etf-planner-scenarios.json`에 따로 저장합니다. 연결 상태는 **가정 저장** 창 아래쪽에서 봅니다.
- 열 때·가정 저장 창을 열 때·45초마다·탭 복귀 시 가져옵니다. 이름 붙인 저장·삭제는 바로, 슬라이더 조정은 5초간 더 바꾸지 않으면 올리고, 앱 전환·탭 닫기 시 기다리던 변경을 바로 올립니다.
- 충돌 확인 창은 없습니다. 이름 붙인 저장본은 모든 기기 것을 합치고(같은 저장본은 나중 저장 우선), 삭제는 다른 기기에도 반영됩니다. 현재 조정값은 가장 나중에 바꾼 기기를 따르며, 보기만 한 기기가 덮어쓰지는 않습니다. 숫자 칸을 입력하는 중에는 다른 기기의 새 조정값을 칸에서 나올 때까지 적용하지 않습니다(**입력 중 · 끝나면 동기화**).
- 공개 저장소이거나 파일 형식을 알 수 없으면 올리지 않고 이 기기에만 저장한 채 오류를 표시합니다.

## 분할매수 (`index.html`)

분할매도처럼 **저장된 계획** 목록에서 하나를 고르면 그 계획의 상세 내용과 회차만 표시합니다(휴대폰에서는 목록이 위에 표시). **＋ 추가**로 새 계획을 만들고, 저장하면 그 계획이 선택됩니다. 목록에는 카드 이름(없으면 매수 우선순위 맨 위 종목명, PC는 아래 줄에 종목 코드)과 완료 회차 수 또는 매수대기 상태를 표시하고, 상세 현황은 선택한 계획 기준입니다. 알림으로 들어오면 해당 종목의 계획이 선택됩니다.

상세 화면은 분할매도와 같은 **연결된 전체 보유 종목 → 계획 진행 → 메모 → 회차표** 순서입니다. 계획 진행 카드는 회차표 순서대로 한 칸씩 나눈 띠(완료 초록·부분 체결과 도달 주황·다음 회차 파랑)에 다음 회차 칸 앞을 가리키는 **현재가** 이름표를 달고, 띠 양 끝에 첫·마지막 기준가와 선 이름, 가운데에 상태·완료/전체 회차·체결/남은 수량을 표시합니다. 도달·부분 체결이 있으면 칩과 안내 줄, 아래에 다음 회차 가격과 남은 %를 보여 줍니다. 매수대기도 같은 모양의 한 카드로, 왼쪽이 낮은 가격인 띠에 선택한 선(왼쪽 ○)과 현재가(오른쪽 ●)를 두고 선 쪽을 가리키는 ‹ 무늬로 하락을 기다리는 방향을 보여 줍니다. 가운데에는 상태 칩과 선까지 남은 하락 %, 맨 아래에는 알림 스위치를 표시하고, 도달하면 현재가가 선 왼쪽으로 넘어가며 주황 띠·선 대비 %로 바뀝니다. 보유 목록에는 연결된 종목의 계좌·수량·평가액·비중을 표시하고, 금액으로 관리하는 항목과 평가에 필요한 시세·환율을 기다리는 항목도 구분합니다. 매수대기에도 같은 보유 목록·계획 진행·메모 구성을 사용합니다(회차표 대신 알림 안내 한 줄). 메모는 글자 수를 확인하고 **저장**합니다. 목록의 카드 이름은 기본 종목명(자산 배분 종목 이름)이며, PC 연필·휴대폰 길게 누르기 또는 계획 수정 창의 **카드 이름**에서 바꿉니다. 카드 이름을 비우면 종목명으로 돌아가고 자산 종목 이름은 유지합니다.

매수·매도의 연결 보유 목록은 같은 작은 화살표와 행 구성을 사용합니다. **종목명 → 계좌·실제 코드 → 보유 수량·평가액·비중** 순서로 배치하고 금액·비중은 보유 수량 바로 옆에 표시합니다. 매도에는 계좌·코드 옆에 남은 매도 계획 수량도 표시합니다. 평가액·비중은 자산현황의 실제 ETF 시세·환율과 전체 자산 분모로 읽고 매도 계획의 환율로 바꾸지 않습니다. 각 항목과 목록 합계에 평가액·현재 비중을 표시하며, 필요한 시세·환율이 없으면 평가 대기와 `—`로 구분합니다. 기존 단일 매도 계좌 선택 화면에도 평가액·비중을 표시합니다.

연결 보유 목록의 **↑ / ↓**로 계좌·ETF의 매수 우선순위를 바꿉니다. 맨 위 항목이 새 회차의 **매수 반영 대상**이며, 화면 제목·목록 카드의 종목명도 이 항목을 따릅니다(자산 종목 이름은 그대로). 해당 ETF 가격으로 계획 주수·회차 간격·미리보기·알림을 함께 계산합니다. 가격·알림의 기준 티커와 전체 계좌 보유 비중·목표는 유지합니다. 이미 시작한 회차는 첫 체결 당시의 계좌·ETF·가격·계획 수량으로 추가 체결·취소하고, 다른 ETF의 주수는 합계로 섞지 않습니다. 순서를 바꾸기 전에는 처음 계획을 붙인 자산 항목이 맨 위입니다. 매수대기도 순서를 저장하며, 돌파 계획으로 바꿀 때 같은 대상을 사용합니다. 순서는 화살표 입력 때만 저장하고 조회·불러오기에서 새 필드를 만들지 않습니다.

플래너 탭 줄의 **분할매수**에서 등록한 자산 배분 종목을 골라 목표 비중까지 나눠 사는 계획을 관리합니다. 현재 비중과 목표까지 남은 금액은 같은 기준 종목·실제 ETF 코드로 연결된 **전체 계좌** 기준이며, 자산현황과 같은 기준 총자산을 사용합니다. 이름이나 큰 분류가 비슷한 다른 상품은 합치지 않습니다. 종목은 창 위 검색칸에서 이름·종목 코드·그룹·소분류로 찾습니다(띄어 쓴 낱말이 모두 들어간 종목, Enter는 첫 종목). 선택 목록에는 개별 항목의 보유량·비중도 유지합니다. 이미 계획이 있는 종목을 고르면 그 계획을 엽니다. 종목 이름·목표 변경과 그룹 이동이 그대로 연결됩니다. 회차를 체크하면 자산 배분 보유량에도 더합니다(아래 **자산 배분 연동**, ‘점검완료’는 바꾸지 않음). 종목을 삭제하면 그 종목의 분할매수 계획도 함께 삭제됩니다.

- **이동평균선 돌파(기본)**: 단계(시선·일선·주선·월선)를 고릅니다. 목표 비중은 아래 **자산 배분 연동**의 자산 배분 목표를 읽기 전용으로 표시하며 계획에 따로 저장하지 않습니다. 목표 가격은 선택 입력입니다. 비우면 **마지막 매수 평균선**을 골라 그 선의 도달 회차까지 목표 금액을 나눠 삽니다. 수정 창에서 종료선을 바꾸거나 목표 가격을 다시 넣을 수 있습니다. 매수 금액은 자산 배분 목표와 전체 계좌 보유액으로 자동 계산하며 직접 고칠 수 있습니다(**다시 계산**으로 되돌림). 자산 배분에서 목표를 바꾸면 그 저장에서 총 매수 금액도 새 목표의 자동 금액으로 다시 계산합니다(직접 고친 금액 포함, 목표를 지우면 금액 유지). 저장 예산을 유지하면서 새 회차는 전체 목표까지 남은 금액 안에서 배분합니다. 다른 계좌 보유량·시세가 바뀌면 회차와 알림도 같은 기준으로 갱신하고, 기존 체결과 부분 체결의 고정 잔량은 보존합니다.
  - 목표 가격을 넣으면 단계마다 다음 단계 가격까지 3번(단계 가격·⅓·⅔ — 다음 단계가 더 낮거나 없으면 1차만) 나눈 회차 중 **목표 가격보다 낮은 회차**와 마지막 **목표가** 회차(목표 가격)에 같은 금액씩 삽니다. 현재가가 회차 가격 이상이면 도달입니다.
  - 미체결 회차 가격은 시세 파일의 이동평균을 따라 움직입니다. 회차표는 **회차 · 기준가 · 매수 · 체결 · 알림** 열(PC는 상태 열 추가)이고, **매수** 칸에 **8주**처럼 회차 예산과 표시 가격으로 살 수 있는 수량을 내림해 표시합니다. 도달 회차는 회차 이름 아래 **도달**을 표시합니다. **체결** 칸에 누적 체결 수량을 입력하면 실제 체결량만 자산 배분에 반영하고, 체크하면 표시한 수량까지 전량 체결합니다. 첫 체결 때 회차의 원래 계획 수량·가격을 고정하므로 시세가 바뀌거나 단계가 사라져도 잔량은 유지됩니다. 잔량 예산을 먼저 남겨 두고 나머지 예산만 지금 이동평균 기준 새 회차에 나눕니다. 예산으로 1주도 살 수 없거나 환율·가격이 없으면 체결 입력·완료 체크가 비활성화됩니다. 시세가 없는 단계는 건너뜁니다. 목표 가격이 있는 계획은 이동평균이 하나도 없어도 목표가 회차를 표시하고, 가격을 비운 계획은 마지막 매수 평균선의 시세가 채워질 때까지 새 회차를 기다립니다.
  - 부분 체결·완료 회차의 **누적 체결 주수**만 카드에서 고칩니다. 입력칸과 카드의 체결·잔량 요약은 주수이며 체결금액 입력은 없습니다. 주수를 고치면 자산 배분 보유량과 배분 계산용 금액을 자동으로 맞춥니다. 계획 수량까지 체결해야 완료하며, 완료 후 수량을 줄이면 부분 체결로 돌아갑니다. 수량 없는 옛 체결은 자산 배분에 이미 반영된 주수를 보여 주며, 주수를 입력·수정할 때 기록에 저장합니다.
  - 데이터 저장소 수집 작업이 이 종목의 전체 시세(일봉 N일선)와 60분봉 N선을 계획 종목처럼 받습니다. 저장한 뒤 다음 수집(장중 30분마다)부터 채워지고, 60분봉 긴 선은 과거 봉을 받는 동안 며칠 걸릴 수 있습니다. 시세 종목 코드가 있는 종목만 쓸 수 있습니다.
- **매수대기**: 원하는 이동평균선의 기간(1~400)과 시선·일선·주선·월선을 고릅니다. 예산·목표 가격 없이 저장하며, 현재가가 그때의 선택한 이동평균선 이하가 되면 알립니다. 새 시세마다 선 값이 갱신되고 주선·월선은 진행 중인 봉도 포함합니다. 카드에 현재가·선 가격·선까지 남은 %와 대기/도달 상태를 표시하며, 대기만으로 보유량이나 매수 예정액은 바뀌지 않습니다. 도달 알림을 켠 뒤 동기화와 기기 알림 수신을 연결하세요. 같은 조건에서는 반복하지 않고 선을 바꾸면 새 기준으로 알립니다. 수집 사이의 순간적인 도달은 놓칠 수 있습니다.
- **기존 직접 입력 기록**: 새 계획의 직접 입력 선택과 회차 추가는 제거했습니다. 기존 회차·체결·자산 반영은 유지하며, 기록이 없는 계획은 돌파·대기로 바꿀 수 있습니다. 회차별 매수 가격·계획 주수·예정일·조건·예정액(만원)을 정합니다(가격 × 수량으로 예정액 계산). 체결은 누적 주수만 입력합니다. 주수 없는 옛 회차도 예정액·가격·환율이 있으면 계획 주수를 내림해 표시합니다. 계산할 수 없으면 계획에 주수를 넣습니다. 부분 체결도 배분 계산에 포함하고, 미체결 잔량만 남은 예정액에 넣습니다. 체결 주수 정정은 카드에서 하고, 수정 창에서는 계획 기준을 유지합니다. 마지막 회차 가격이 첫 회차보다 높으면 상승(현재가 ≥ 회차 가격이면 도달), 아니면 하락(≤)으로 봅니다. 체결 기록이 있는 방식에서는 다른 방식으로 바꾸지 않습니다.
- 카드 제목 아래에는 현재가(시세 파일), 완료/전체 회차(예: **12/54회 분할매수**, 부분 체결이 있으면 · 부분 1), 다음 회차까지 남은 %를 보여 주고, 현재가가 닿은 미완료 회차를 **도달**로 표시합니다.
- **일반 추종 ETF 주수 환산**: **자산 → 자산 배분 → 종목 수정**에서 기존 기준 티커(예: 미국 ETF)는 유지하고 **실제 매수 ETF 코드**를 따로 넣습니다. 회차 예산(만원) ÷ 실제 ETF 원화 가격을 정수 주수로 내림해 **매수 주수·예상 금액·잔액**을 표시합니다. 새 체결이 들어갈 회차(미체결)가 모두 같은 계좌·실제 ETF면 회차표 위 **매수 종목** 한 줄에 계좌·코드와 (미체결 회차가 모두 같을 때) 회차 예상 금액·잔액을 한 번만 보입니다. 다른 계좌·ETF로 체결한 회차, 금액이 다른 회차, 부분 체결의 남은 예상 금액만 그 회차 아래에 따로 표시합니다(실제 ETF 코드를 넣기 전에 같은 계좌로 체결한 회차는 따로 표시하지 않음). 직접 입력 회차의 가격·미체결 기준 수량은 기준 티커 단위이며, 예정액을 넣지 않았다면 기준 수량 × 기준가 × 환율로 예산을 환산합니다. 실제 ETF가 달러 가격이면 원화 예산을 환율로 나눕니다.
  - **이미 보유한 ETF의 매수 반영**: 해당 계좌·그룹의 기존 자산 종목을 수정하고, 분할매수 계획에서도 그 항목을 고릅니다. 이후 연결 보유 목록의 화살표로 다른 계좌·ETF를 맨 위로 올리면 새 회차의 반영 대상을 바꿀 수 있습니다. 계획 창에 **매수 반영 대상(자산 배분 → 그룹 → 종목)**과 현재 보유량을 표시합니다. 체결분은 선택한 항목의 id에만 더하므로 같은 ETF 코드가 다른 계좌에 있어도 영향을 주지 않습니다. 보유 주수 없이 금액으로 관리하는 항목은 체결 금액을 더합니다. 이미 기록한 회차의 수량을 늘리거나(이어 사기) 줄이거나 0·체크 해제로 취소하면(되팔기), 처음 산 계좌가 아니라 **지금 매수 우선순위 1번 계좌**에 바뀐 양만 반영합니다. 처음 산 계좌를 지웠거나 2번 이하로 내려도 같습니다. 1번 계좌 보유량이 모자라면 0까지만 빼고 알립니다. 1번 계좌의 실제 매수 ETF 코드가 회차와 다르면 주수 단위가 달라 처음 반영한 계좌를 그대로 고칩니다.
  - **같은 종목 코드의 여러 계좌 줄**은 한 계획을 함께 씁니다. 다른 계좌 줄을 골라도 새 계획 대신 기존 계획을 열고(목록에 **계획 있음**), 이미 둘 이상이면 경고만 표시합니다. 같은 코드의 다른 계좌로 살 때는 예상 금액·잔액을 붙이지 않습니다. 계획이 붙은 줄이나 그 그룹을 자산 배분에서 삭제하면 계획·체결 기록·알림 설정을 기준·실제 코드가 같은 남는 줄 중 매수 우선순위가 가장 앞선 줄로 옮깁니다. 종목의 목표 비중은 대표 계좌 줄 하나에 두며, 목표가 있는 줄을 지우면 같은 그룹·소분류에 남는 같은 코드 줄(계획을 받는 줄 우선)로 목표도 옮깁니다(받는 줄에 목표가 있으면 더함). 알림 ID가 새 줄 기준으로 바뀌어, 도달했지만 아직 사지 않은 회차는 한 번 다시 알릴 수 있습니다. 남는 같은 종목 줄에 이미 계획이 있거나 옮길 줄이 없으면 계획도 함께 삭제합니다.
  - 실제 ETF 가격은 자동 시세를 우선합니다. 시세가 없으면 종목 수정 창의 **매수 ETF 현재가**를 직접 넣고, 둘 다 없으면 체결 입력·체크를 비활성화합니다. 가격·환율 기준은 계획 창에 표시합니다. 수집 작업은 기준 티커의 이동평균을 유지하면서 실제 ETF의 현재가도 장중에 수집합니다.
  - 보유 수량과 누적 체결 수량은 실제 ETF 주수입니다. 첫 체결 때 실제 ETF 코드·가격·통화·계획 주수를 고정해 부분 체결 잔량을 유지하고, 취소하면 기준 수량 입력과 자산 반영을 되돌립니다. 기준 가격 도달·휴대폰 알림은 기존 기준 티커를 계속 사용합니다. 실제 ETF 코드를 비운 기존 기록의 계산은 그대로입니다.
- 휴대폰 알림: 회차표의 **알림** 칸 스위치(또는 카드 위 **전체 ON**)를 켜면 같은 도달 기준으로 알립니다(아래 **휴대폰·PC 매매 기준 알림**, 라벨 `분할매수 25선 2차`·`분할매수 목표가`·`분할매수 3차`). 자산 배분에서 그 종목에 시세 종목 코드가 있고 계획 통화가 그 시장 통화와 같아야 합니다(미국 심볼은 달러). 이동평균선 돌파·매수대기는 이평선이 움직여도 같은 알림으로 이어지고, 기존 직접 입력에서 알림을 켠 종목은 수집 작업이 장중 실행마다 현재가를 받습니다.

기존 자산 기록의 종목별 `buyPlan`을 그대로 사용하므로 데이터 이전 없이 연결됩니다. `js/assets-store.js`에서 자산 페이지와 같은 저장·동기화를 사용하며, 플래너의 동기화 창에서도 **분할매수·자산 JSON 백업·복원**과 보관한 복구 기록을 내려받을 수 있습니다.

## 자산 배분 연동 (분할매도·재매수·분할매수 ↔ 자산 배분)

**기준 티커에 연결된 전체 계좌 통합 매도**: 자산 배분에서 기준 티커가 같은 항목은 ISA·연저펀·일반 계좌와 관계없이 하나의 분할매도 계획에 자동으로 포함합니다. 기준 종목을 직접 보유한 항목과 실제 거래 ETF 코드를 따로 등록한 추종 ETF를 함께 표시합니다. 새 보유 종목도 같은 기준 티커로 등록하면 미체결 회차에 자동 포함하며, 이미 체결한 회차의 종목과 계획 수량은 유지합니다.

**연결된 전체 보유 종목 → ↑↓**로 먼저 매도할 종목·계좌를 정합니다. 목록 위에서부터 한 계좌의 매도 예정 물량을 먼저 배정하고, 소진하면 다음 계좌로 넘어갑니다. 순서를 바꾸면 미체결 회차에 적용하며 부분 체결·완료 회차는 유지합니다. 새로 연결한 종목은 지정한 순서 뒤에 추가됩니다. 순서를 바꾸기 전에는 자산 목록 순서입니다.

회차표는 분할매수 회차표와 같은 **회차 · 기준가 · 매도 · 체결 · 알림** 열(PC는 상태 열 추가)입니다. 표 위 **매도 종목**에는 지금 매도 중인 계좌·종목(다음 회차를 파는 종목, 그 회차를 여러 계좌로 나눴으면 그 계좌들)만 표시합니다. 매도 우선순위를 바꾸거나 앞 계좌를 다 팔면 바뀌며, 뒤 계좌가 팔 회차에도 회차 안에 계좌 이름을 더하지 않습니다. 지금 매도 중이 아닌 계좌로 이미 체결한 회차만 회차 아래 작은 줄에 계좌를 둡니다. 우선순위 경계에서 여러 계좌로 나뉜 회차는 회차 줄에 합계, 아래 계좌별 줄에 매도 주수와 체결 입력칸을 둡니다(종목 이름 끝 괄호가 있으면 그 꼬리표를 굵게). 화면 제목·목록 카드의 종목명은 계획 이름이 자산 배분에서 고른 종목 이름이면 매도 우선순위 맨 위 종목을 따릅니다(직접 쓴 계획 이름·자산 종목 이름은 그대로). 기준 티커의 가격·환율·예전 평가액이 바뀌어도 주수로 관리하는 실제 보유량의 계획 수량은 변하지 않습니다. 금액만 관리하는 항목은 실제 종목 시세로 주수를 환산합니다.

누적 체결은 각 계좌의 실제 종목 주수로 입력하고 해당 항목에서만 차감합니다. 계좌별 잔량은 그 계좌 칸에 계획 주수를 입력하고, 회차 체크는 모든 연결 계좌의 남은 계획을 전량 체결한 것으로 기록합니다. 부분 체결·추가 체결·수량 정정은 계좌별 차이만 반영하고, 0 입력·체크 해제는 원래 계좌로 복원합니다. 시세·필요한 환율·보유량을 확인할 수 없거나 보유량을 초과하면 체결을 막습니다. 첫 체결 때 회차 계획과 종목을 고정하며 각 계좌의 체결 가격·환율도 첫 체결 때 유지합니다. 옛 단일 계좌 체결은 보존합니다. 매도 기준선·도달 알림은 기준 티커를 계속 사용합니다.

플래너 화면과 자산 현황의 자산 배분을 종목 코드로 연결합니다.

- 연결: 계획·재매수 종목과 종목 코드가 같은 자산 배분 종목(계좌)입니다(대소문자·국내 코드 앞 `A` 무시, `비트코인` = `BTC-USD`). 분할매수는 계획이 붙은 종목과 명시적으로 연결된 실제 ETF도 포함합니다. 분할매수 새 체결은 연결 보유 목록의 맨 위 자산 항목에 반영하며 화살표로 그 계좌·ETF를 바꿉니다. 기존 체결의 추가·취소는 당시 반영 계좌를 유지합니다. 다른 계획에서 종목 코드가 없거나 같은 코드가 없으면 지금처럼 체크만 합니다.
- **목표 비중 단일 기준**: 자산 현황 → 자산 배분의 목표 비중(종목·소분류·그룹)만 저장하고 분할매수·분할매도·재매수는 그 값을 그릴 때마다 읽습니다. 예를 들어 EDV 목표를 21% → 21.5%로 저장하면 같은 기준 코드의 분할매수·분할매도·재매수에 바로 21.5%가 표시되고, 같은 기기의 다른 탭은 즉시, 다른 기기는 자산 기록 동기화 뒤 같은 값을 받습니다(받은 쪽에서는 다시 계산하지 않음).
  - 목표를 바꾼 저장에서 연결된 분할매수(이동평균선 돌파)의 총 매수 금액을 새 목표 × 기준 총자산 − 전체 계좌 보유 + 이미 체결한 금액으로 다시 계산해 같은 자산 기록에 둡니다. 체결·부분 체결 기록, 단계·시작선·목표 가격, 알림·우선순위, 자산 반영 기록과 분할매도·재매수 기록은 바꾸지 않습니다. 보유량·시세만 바뀐 저장은 다시 계산하지 않습니다.
  - 예전에 분할매수 계획 창에서 따로 넣은 목표(`lines.target`)는 자산 배분에 목표가 없을 때만 계속 쓰고 화면에 `(계획 목표)`로 표시합니다. 자산 배분 목표를 바꾸거나 계획 창을 저장할 때 자산 배분 목표가 있으면 지웁니다.
- 계획 화면 제목 아래 **자산 배분** 줄: 연결 계좌 수·평가액, 현재/목표 비중, 목표까지(목표 초과) 금액. 목표는 분할매수와 같은 규칙으로 연결 종목 목표의 합, 없으면 연결 종목이 전부 포함된 그룹 목표 `(그룹)`·소분류 목표 `(소분류)`입니다.
- 종목 검색: 분할매수·분할매도·재매수 추가 창 위 종목 칸은 같은 검색 목록(이름·종목 코드·그룹, 띄어 쓴 낱말 모두 포함)입니다. 누르거나 Enter로 고르면 한 줄로 접히고 **변경**으로 다시 검색합니다. 분할매도·재매수는 목록에 없는 종목을 아래 칸에 직접 입력하며, 맞는 종목이 없을 때 검색어를 종목 코드(분할매도)·종목 이름(재매수)으로 넘길 수 있습니다.
- 보유량 가져오기: 분할매도 창 검색에서 자산 배분에 등록한 종목을 고르면 코드·이름·통화와 연결 계좌의 보유량을 함께 넣습니다. 같은 기준 종목은 여러 계좌에 있어도 한 번만 표시하고, 추종 ETF는 기준 종목으로 고릅니다. 직접 코드를 넣은 뒤 **보유량 가져오기**도 사용할 수 있습니다. 모두 같은 거래 코드의 수량이면 수량 합, 아니면 평가액 합(만원)으로 넣으며, 체결 기록이 있으면 종목·계획 보유량은 유지합니다.
- 재매수 이탈 전 보유: 입력칸 없이 종목 코드가 같은 자산 배분 계좌의 보유(수량 합 또는 평가액 합, 미국 종목은 달러로 환산)를 읽기 전용으로 보여 주고 손절 수량을 계산합니다. 손절·재매수 기록이 없는 동안은 자산 배분 보유를 따라가며, 첫 손절을 기록하면 그때 보유로 고정합니다(체크 기록을 모두 지우면 다시 따라감). 시세 수집 작업의 알림이 쓰는 저장값은 재매수 화면에서 값을 고치거나 **변경 저장**·종목 창 저장을 할 때 맞춥니다. 자산 배분에 없는 종목은 이전에 저장한 보유로 계산하고 등록을 안내합니다.
- 체크하면 보유량 반영: 분할매도 회차·재매수 손절은 빼고, 재매수 회차·분할매수 회차는 더합니다.
  - 통합 분할매도는 회차의 계좌별 누적 체결을 해당 항목에 바로 반영합니다. 다른 매매와 옛 단일 계좌 매도는 연결 계좌가 하나면 바로 반영하고, 여럿이면 **자산 배분에 반영** 창에서 계좌를 고릅니다 — 계좌 이름을 누르면 그 계좌로 모두, 여러 계좌로 나눴으면 칸을 고칩니다. 같은 계획에서 마지막으로 고른 계좌(재매수 회차는 손절한 계좌)가 먼저 선택돼 있습니다. **반영 안 함**은 체크만, **취소**는 체크하지 않습니다.
  - 양: 수량을 넣은 종목은 주(비트코인 0.00000001 단위), 금액만 넣은 종목은 지금 평가액 기준 만원. 분할매도는 누적 체결 주수 × 회차 기준가, 재매수는 기록한 수량 × 가격, 분할매수는 누적 체결 주수와 자동 계산한 금액입니다. 주수 없는 옛 매수·매도 계획도 회차 가격·환율로 계획 주수를 계산해 체결을 입력합니다.
  - 시세를 따라가는 금액 종목은 입력 금액 칸을 같은 비율로 바꿔 입력 대비 수익률을 유지합니다. 보유량은 0 아래로 내려가지 않고, 다 판 종목은 보유 수량 0(평가액 0)으로 남습니다.
  - 분할매수·분할매도는 체크 전부터 누적 체결 주수로 부분 체결을 입력합니다. 추가 체결·주수 정정은 기존 반영 기록을 맞춰 자산에는 차이만 반영하며, 금액은 자동으로 계산합니다. 재매수 손절·재매수 체결 수량·가격 정정도 같은 방식입니다. 정정은 반올림 전 양을 기준으로 맞춰서, 잘못 줄여 반영량이 0이 됐다가 바로잡아도 원래 양으로 돌아오고 추종 ETF 주수 내림이 쌓이지 않습니다.
- 체크를 풀면 반영한 양을 그대로 되돌립니다. 재매수 **체크 기록 초기화**는 되돌릴지 한 번 더 묻습니다. 계획·종목을 삭제해도 자산 배분은 그대로 둡니다(실제 체결).
- 반영 기록은 자산 기록(`etf-planner-assets.json`)의 `allocation.trades`에 부분 체결·완료 기록이 있는 동안 두고 자산 배분과 함께 동기화합니다. 자산 현황의 종목 수정 창에서 그 종목에 반영한 내역을 봅니다.
- 이 기능 전에 체크한 회차는 반영 기록이 없어 풀어도 자산 배분을 바꾸지 않습니다. 달러선물은 종목 코드가 없어 연결하지 않습니다.

## 자산 현황 (`assets.html`)

엑셀로 관리하던 자산 정리를 옮긴 페이지입니다. 플래너 탭 줄의 **자산**으로 들어갑니다(돌아갈 때는 오른쪽 위 **플래너**).

- **투자구성**(엑셀 분할 정리): 지역·자산 분류별 평가액과 현재·목표 비중, 목표까지 남은 금액·초과 금액을 한눈에 봅니다. 목표 비중은 종목 → 소분류 → 그룹 → 분류로 합산합니다. 하위 목표가 하나라도 있으면 그 합계를 쓰고, 전부 비어 있으면 기존 직접 입력한 목표를 씁니다. 상위 목표는 합산 중에는 직접 수정하지 않으며, 저장된 기존 목표는 계산만으로 바꾸지 않습니다.
- **자산 배분**(엑셀 Sheet2): 그룹·종목과 현금을 관리합니다. 금액은 만원, 모든 목표 비중은 직접 넣은 기준 총자산(비우면 종목 + 현금 합계) 대비입니다. 종목별에서 목표를 고치면 투자구성에도 자동 반영됩니다. ‘점검완료’는 직접 체크하는 작업 기록으로, 현재 비중이나 목표 도달을 자동 판정하지 않고 계산에도 영향을 주지 않습니다. 현금(원화·달러, 빼는 항목)은 따로 적고 달러는 현물 환율로 환산합니다. 현금 합계는 큰 분류 창에서 **현금 합계**를 체크한 분류 하나에만 더하며, 다른 분류에 체크하면 저장할 때 그 분류로 옮깁니다.
  - 그룹 추가·수정 창의 **큰 분류**에서 **해외 · 중국**을 선택할 수 있으며, **해외 · 인도**가 있으면 바로 다음에 표시합니다. 중국 분류가 없는 기존 기록은 이 분류를 선택한 그룹을 저장할 때 추가합니다. 이전 **중국 · 주식** 기록도 기존 연결을 유지하며 **해외 · 중국**으로 표시합니다.
  - 기준 총자산은 억·만원으로 표시하고 그대로 수정할 수 있습니다. 숫자만 넣으면 기존처럼 만원 단위로 저장하며, 비우면 종목 + 현금 합계를 기준으로 씁니다.
  - **점검완료 일괄해제**를 누르면 검색 결과와 관계없이 모든 그룹의 종목 체크를 해제하고 저장·동기화합니다. 해제할 체크가 없으면 버튼을 비활성화합니다.
  - 종목별 목록 위 **종목 검색**에서 이름·티커·실제 ETF 코드·그룹·소분류로 찾습니다. 대소문자·이름의 띄어쓰기를 구분하지 않고, 공백으로 나눈 검색어를 모두 포함한 종목만 표시합니다. **초기화** 또는 Esc로 전체 목록을 다시 봅니다. 검색 중에도 평가액·비중은 전체 자산 기준이며, 검색어는 저장·동기화하지 않습니다.
  - 종목 평가액: 보유 수량을 넣으면 수량 × 현재가(달러는 × 환율, 0이면 평가액 0), 금액만 넣으면 넣을 때의 시세 대비 변동만큼 따라갑니다. 실제 매수 ETF 코드를 넣으면 해당 ETF 가격과 주수로 평가합니다. 코드를 비운 기존 기록은 추종하는 미국 ETF 시세 비율로 따라가는 방식도 유지하며, 종목 코드가 없으면 넣은 금액 그대로입니다.
  - 플래너의 분할매도·재매수·분할매수 체크가 같은 종목 코드 종목의 보유량을 바꿉니다(위 **자산 배분 연동**).
  - **목표 대비**: 그룹과 목표가 있는 종목은 현재 비중 − 목표 비중을 %p로 표시합니다(예: 목표 20%·현재 23% → `+3.0%`, 현재 18% → `-2.0%`, 소수 첫째 자리 반올림). 표시 값이 ±1.0%p 이내면 기본 색, 넘으면 초과(+)는 빨강·미달(−)은 파랑입니다. 종목 목표가 같은 기준 코드·실제 ETF로 연결된 다른 계좌까지 덮으면 그 종목 혼자가 아니라 `합계 N%`(연결 계좌 합계, 분할매수 ‘전체 계좌’와 같은 기준)와 목표를 비교합니다. 그룹은 차이가 1.0%p를 넘어도 그 안의 종목이 모두 회색(목표 대비 ±1.0%p 이내이거나 매수중·매도중)이면 기본 색입니다. 목표가 없는 종목은 매수중·매도중이거나 연결 계좌 합계 비교에 들어가거나 비중이 0%일 때만 회색으로 보며, 어느 목표에도 들지 않은 보유가 있으면 그룹 색을 유지합니다. 폰에서는 현재·목표 아래 줄에 표시합니다. 투자구성의 분류 줄은 기존처럼 목표까지·목표 초과 금액을 보여 줍니다.
  - **매수중·매도중**: 끝나지 않은 분할매수(같은 코드의 다른 계좌 포함)에 편입된 종목은 빨강 ‘매수중’, 끝나지 않은 분할매도에 편입된 종목은 파랑 ‘매도중’을 종목명 옆에 표시하고, 목표와 차이가 커도 초과·미달 색을 쓰지 않습니다. 모든 회차를 체결한 계획(분할매수 ‘매수 완료’, 분할매도 전 회차 체크)은 표시하지 않습니다. 이동평균선 돌파 분할매수는 플래너가 이 기기에 받아 둔 이동평균 시세로 남은 회차를 확인하며, 시세가 없으면 총 매수 금액을 다 쓸 때까지 매수중으로 봅니다. 재매수는 이 표시에 넣지 않습니다. 계산·기록은 바꾸지 않습니다.
- **월별 손익**: 연도마다 계좌 목록, 달마다 실현손익·계좌 잔액을 기록합니다. 월 입력 창에는 신한의 기본계좌+ISA·연금저축·배당, 키움증권의 실현손익·달러 배당 전용 칸이 있습니다. 키움 배당은 달러 금액과 원·달러 125개월 평균 환율로 원화 환산액을 자동 계산하며, 별도의 원화 배당 입력은 없습니다. 새 배당의 환율은 수집된 원·달러 125월선으로 자동 적용합니다. 평균선이 없으면 다른 환율로 대체하지 않으며 입력 창의 평균선 갱신으로 시세를 불러옵니다. 저장된 배당은 당시 환율·환산액을 유지하며, 옛 달러·원화 기록의 환율도 역산해 사용합니다. 옛 배당의 달러 금액을 고치거나 평균선을 갱신하면 125월선을 적용합니다. 금액을 넣은 항목만 저장하고 원화 합계를 자동 계산합니다. 다른 증권사·항목도 추가할 수 있고 기존 합계만 입력한 기록도 그대로 사용합니다. 대출 관련 입력·표시는 없으며 옛 대출 계좌는 자산·수익률 계산에서 제외합니다. 이자 입력은 없으며 기존 이자 기록은 보존합니다. 선물·옵션 손익은 월 입력 창의 **선물·옵션** 칸에 달마다 넣고(월별로 넣는 해는 넣지 않은 달 줄에 **선물·옵션 미입력** 표시), 달을 모르는 금액만 선물·옵션 행(연도 설정)에 넣습니다. 두 값은 함께 더합니다. 월 수익률은 실현손익 ÷ 그 달 총자산입니다. 맨 위 카드는 고른 연도의 누적 수익률(월 수익률 합)을 S&P 500 누적 수익률과 선 그래프로 비교하고, 그래프 아래에 **월 손익 합 + 선물·옵션 = 누적**을 보여 줍니다(월별 선물·옵션은 그 달 그래프에, 달을 모르는 금액은 마지막 기록 달에 더함)(기준은 [js/ledger-benchmark.js](js/ledger-benchmark.js)의 `ledgerChartData` 주석). 올해는 실현손익을 기록한 마지막 달 말까지, 지난해는 S&P 500 연간 수익률과 비교합니다. **금액**으로 바꾸면 월 실현손익 누적을 원 단위로 그리며 이 선택은 이 기기 화면 설정에만 기억합니다. 연도는 맨 위 칩 줄(가로로 밀기, 끝의 ＋로 연도 추가)에서 고르고, 연환산은 월별 표의 합계 줄에 있습니다. 잔액을 넣은 달에 앞뒤 달에는 잔액이 있는 계좌가 비어 있으면(빈칸은 0원으로 더해 그달 수익률이 높게 나옴) 총자산 아래 **빈 계좌 N개 · 확인**과 월 입력 창의 안내로 알려 줍니다. 아직 열지 않았거나 해지한 뒤 비운 계좌는 표시하지 않으며 기록은 바꾸지 않습니다. 선물·옵션은 월별 값은 그 달 총자산, 달을 모르는 금액은 마지막 달 총자산 기준으로 연 수익률에 더하고 연환산에서는 제외합니다. 연평균 수익률은 계산 가능한 해들의 연 수익률 산술평균이며, 손익이 없는 해·잔액이 부족한 해는 제외합니다. 연도별 요약 아래 **S&P 500 비교**는 2021년부터 지난해까지 완료된 연도만으로 내 연평균 수익률, S&P 500 Total Return(배당 재투자·달러) 연간 수익률의 평균, 두 값의 차이(%p)를 보여 줍니다. 두 평균 모두 연 수익률 산술평균(연복리 CAGR 아님)이고 같은 연도끼리 비교합니다. 해가 바뀌면 비교 기간이 자동으로 늘어납니다. 진행 중인 올해는 평균에 넣지 않고, 실현손익을 기록한 마지막 달 말까지 내 누적 수익률과 S&P 500 월말 누적 수익률(S&P DJI 월간 대시보드)을 월 단위로 따로 비교합니다. S&P 500 월말·연말 종가는 공개 GitHub Actions(`.github/workflows/sp500-tr.yml`, 매월 1~7일)가 Yahoo Finance의 `^SP500TR`에서 받아 `data/sp500-tr.json`에 자동 기록합니다. 받은 종가로 다시 계산한 수익률이 [js/ledger-benchmark.js](js/ledger-benchmark.js)의 S&P DJI 공표치(최근 연간·확인한 월말)와 ±0.02%p 안일 때만 기록하고, 새 월말 종가가 있을 때만 커밋합니다. 공표치가 있는 달·해는 공표치를 우선하며, 아직 값이 없는 달·해는 비교에서 빼고 반영 전으로 표시합니다. 월별 손익·저축 계획의 금액은 입력 중에도 쉼표로 표시하고 숫자로 저장합니다. 손익·선물·옵션 칸(배당·잔액 제외)은 오른쪽 **+/−** 버튼으로 부호를 바꿉니다(삼성 키보드·iPhone 숫자 키패드에는 `-` 키가 없음). 자동 합계가 된 실현손익 합계 칸에서는 숨깁니다.
- **저축 계획**(엑셀 복리 저축 계산 등 보이는 시트): 연도를 펼쳐 월별 실제 저축총액을 직접 기록·수정합니다. 마지막 실제 기록 다음 달부터 시나리오(월급·기부·사용금액·증가율·수익률·나이별 변경)로 계산하고 나이별로 비교합니다. 연도 요약에서 기부금 합계를 보고, 펼친 연도에서 월급 기부와 투자수익 기부 내역을 확인합니다.
- **할부 계산**(엑셀 무이자계산): 같은 구매를 일시불과 직접 입력한 두 무이자 기간으로 결제할 때 월 납부액과 보유자금 수익을 비교합니다. 기간은 1~120개월 정수이며 기본값은 12·36개월입니다. 저축계획의 마지막 실제 기록을 기준 순자산으로 참조하거나 시뮬레이션용 금액을 직접 입력하고, 각 할부 종료 시점의 순자산·일시불 대비 금액과 비율 및 월별 차이를 확인할 수 있습니다. 수익률은 남은 구매대금에만 적용하고 미납 원금은 부채로 차감합니다. 적립·캐시백은 화면·계산에서 제외하며 옛 데이터는 보존합니다. 할인은 기본 미적용이며 선택 할인율·할인한도는 기본 0입니다. 새 비용 입력은 없고 옛 비용은 명시적으로 지우기 전까지 반영합니다. 결제 연월, 마지막 회차 원 단위 보정, 같은 3·5·10년 비교, CSV 및 저장·복원·동기화를 지원합니다. 조건은 별도 구역에 저장하며 실제 자산·저축 기록을 바꾸지 않습니다.
- 저장·동기화: 이 기기 브라우저 + 메인 플래너가 연결한 비공개 데이터 저장소의 `etf-planner-assets.json`(따로 설정할 것 없음). 자산 배분·월별 손익·저축 계획·할부 계산을 따로 맞추며, 두 기기가 지난 동기화 뒤에 고친 칸은 종목·분류·월·연월·체결 회차 단위로 모두 합칩니다(오프라인에서 고친 것도 같음). 같은 칸을 함께 고쳤으면 나중에 저장한 값을 쓰고, 지운 쪽과 고친 쪽이 겹치면 고친 쪽을 남기며, 다른 쪽 기록은 이 기기에 보관하고 화면 위에 주황색으로 알립니다(보관 기록 내려받기·확인). 계좌 잔액 줄처럼 항목 구분이 없는 목록은 한 칸으로 봅니다. 지난 동기화 기준이 없는 기기(새 기기·다른 저장소)에 저장소와 다른 기록이 있으면 합치지 않고 **저장소 기록 사용 / 이 기기 기록 사용**을 고를 때까지 이 기기에만 저장하며, 고르지 않은 쪽은 보관합니다. JSON 백업·복원도 동기화 창에 있습니다.
- 시세: 같은 저장소의 `etf-planner-prices.json`을 바뀌었을 때만 읽습니다(ETag). 자산현황 상단과 동기화 창의 **시세 즉시 불러오기**는 실제 수집을 요청하고 완료된 시세를 보유 평가액·환율에 반영합니다. 평가에 필요한 실제 ETF 시세가 없으면 완료 대신 해당 종목 코드를 안내합니다. 국내·미국 보유 종목도 마감 시각을 기다리지 않고 함께 수집합니다. 보유량·입력 금액·체결 기록과 예약 수집 주기는 유지합니다. 처음 등록한 보유 종목은 다음 일반 수집(비트코인 전용·저녁 추가 수집 제외)에서 장외에도 마지막 종가 한 번을 받고, 이미 받은 시세는 **장 마감 후 하루 한 번**(국내 16:40·미국 06:40) 갱신합니다. 분할매도·재매수·알림에도 있는 종목은 장중 시세를 그대로 씁니다.
